유지하고, 사용자 요청에 맞춰 공개 저장 개수와 다음 촬영까지의 대기를 바꿨다.
AUTO의 CameraX/JPEG 경로와 별도 **RAW 합성** 화면을 유지한다.

## 0.13.0 제어·작업 흐름 변경

RAW 화면은 AUTO 직접 전환과 고정 셔터를 제공합니다. 앱 내 종료는 모드에 걸친 대기 작업을 보호하지만 운영체제의 프로세스 종료 후 RAW 복구를 보장하지 않습니다.
`초점·Pro`에서는 기기 지원에 따라 탭 AF/AE, EV, 수동 ISO·셔터(센서 범위 안에서 최대 1초), 수동 초점, 기기가 제공하는 WB 설정을 사용할 수 있습니다.
최신 결과 메타데이터로 요청 적용을 확인하고 촬영 시 해당 상태를 고정·복원합니다. 같은 렌즈를 다시 열면 Activity ViewModel 안의 설정을 유지하며 다른 렌즈로 바꾸면 자동으로 초기화합니다.
아래의 단일 출력 합성·DNG 알고리즘은 유지합니다. [0.13.0 검증과 한계](PHOTON_0130_VERIFICATION.md)를 참고하세요.
이 문서는 기존 RAW 단일/3프레임 DNG 경로를 설명합니다. 이후 추가된 RAW AUTO 다중 노출 HDR·JPEG 현상은 별도 버전 문서에서 확인합니다.

RAW AUTO HDR의 현재 유효성·역분산 규칙과 측광 1장 대비 암부 회귀는 [0.17.0 검증](PHOTON_0170_VERIFICATION.md)에 있습니다. 아래 동노출 RAW DNG의 기준 가중치 하한을 다중 노출 HDR에 적용하지 않습니다.
## 사용자 계약

- RAW 합성 기본 OFF: 셔터를 누르면 원본 DNG 1장 저장.
- ON: 같은 노출을 목표로 RAW 3장 수신 → 메모리에서 합성 → 최종 DNG **1장만** 공개 저장.
- 정합/메타데이터가 불충분하거나 변경 픽셀이 없으면 기준 원본 DNG **1장**으로 대체한다.
  합성 파일 작성 실패도 미공개 후보를 정리한 뒤 기준 원본 1장을 시도한다.
- 합성 입력 3장은 갤러리나 원본 파일로 저장하지 않는다. 기준 선택 전 합성이 실패하면
  첫 프레임, 선택 후 실패하면 선택된 기준 프레임을 사용한다.
- RAW 수신이 끝나면 촬영 잠금을 해제하고 저장은 뒤에서 계속한다. 촬영 중인 작업을 포함해
  최대 2건만 접수하며, 포화되면 다음 셔터를 막고 대기열 상태를 표시한다.
- 저장 위치는 `Pictures/LUNA PHOTON RAW/`. 기존 사진을 수정하거나 삭제하지 않는다.
- 합성은 저장 파일에만 적용한다. 프리뷰는 가운데를 잘라 표시하며 DNG는 센서 전체다.
- DNG에는 RAW 지원 뷰어가 필요하다. RAW를 JPEG로 현상하는 기능은 아직 없다.
- 실제 셔터만 센서 이미지를 요청한다. 세션/성능 자동 검사는 사진을 촬영하지 않는다.
- v0.7.5 RAW의 후면 AUTO는 두 손가락 조작으로 광학 렌즈 단계를 선택한다.
  단계 사이에 디지털 확대를 적용하지 않으며 현재 실제 광학 배율을 표시한다.

## 후면 AUTO 광학 선택

연결 기기의 기존 논리 RAW 세션은 0.6/1/3/5배 요청에도 같은 물리 센서를 유지했다.
따라서 v0.7.5는 초점거리/센서 너비로 상대 광학 배율을 계산하고, 선택한 물리 센서에
프리뷰와 RAW 출력을 함께 연결한다. 저장에는 그 센서의 특성과 물리 촬영 결과를 사용한다.
물리 결과가 없거나 한 버스트의 센서 ID가 달라지면 다른 센서의 메타데이터로 대신 저장하지 않는다.

핀치의 광학 단계 경계에는 히스테리시스와 200ms 대기를 적용한다. 프리뷰 세션을 반복해서
재연결하는 일을 줄이기 위한 값이며 촬영 버튼을 누른 뒤 추가하는 지연이 아니다.
전환 중에는 셔터를 잠그고, 촬영 중에는 렌즈를 바꾸지 않는다. 지원하지 않는 물리 세션은
해당 화면 모델의 사용 가능 목록에서 제외하고 이전 렌즈 또는 다른 지원 렌즈로 복귀한다.
수동 공개 카메라 선택과 전면 카메라도 유지한다. 검증 범위는
[v0.7.5 기록](PHOTON_075_VERIFICATION.md)에 별도로 남긴다.

## 촬영과 메타데이터

`RawBurstCamera.kt`는 별도 HandlerThread에서 Camera2 세션을 소유한다. 공개 RAW 카메라의
16MP 이하 최대 크기와 1920×1080 이하 프리뷰를 사용한다. ImageReader에는 최대 2장을
유지하고, 이미지를 packed native-endian uint16 direct buffer로 복사한 뒤 즉시 닫는다.
실제 Image.timestamp와 SENSOR_TIMESTAMP가 일치하는 결과만 묶으며 오래된 요청은
burst별 태그로 제외한다. 원본 3개의 버퍼는 합성에서 읽기 전용이다.

프리뷰 AE/AWB가 수렴한 경우만 노출/ISO로 수동 노출 또는 AE lock을 설정한다.
직전 촬영의 수동 상태에서 자동 프리뷰로 돌아오는 도중이면 최대 약 1.5초 동안 새 수렴
결과를 기다린다. 여전히 수렴하지 않았으면 재시도를 안내한다. 렌즈가 정지했고 프리뷰가
PASSIVE_FOCUSED/FOCUSED_LOCKED이면 지원되는 수동 초점 거리 고정으로 AF 재탐색을 생략한다.
나머지는 AF를 획득한 뒤 거리를 고정한다. 준비 요청의 결과만 태그로 구별해 사용한다.
초점 실패는 촬영 실패로 표시한다. 지원되는 경우 NR/EDGE OFF와 렌즈 음영 맵을 요청한다.
요청이 곧 ISP 완전 우회를 의미하지 않으며 저장 영수증에는 실제 NR/EDGE 결과를 기록한다.
열기 12초, 촬영 전체 15초, 초점 준비 2초의 제한과 취소/닫기 경로가 있다.

`RawPhotoStore.kt`는 CFA가 표준 Bayer인지, 프레임 크기·물리 카메라·타임스탬프·노출·잡음
프로필이 유효한지 확인한다. black/noise 배열은 모두 **CFA의 TL/TR/BL/BR 순서**다.
잡음 프로필이 없으면 임의 상수를 만들어 합성하지 않는다. 유효한 `S>0, O=0` 모델은
허용하며 음수 또는 S/O가 모두 0인 모델은 거절한다. DngCreator가 정적 WhiteLevel을
쓰므로 동적 white가 다르면 합성을 거절하고 기준 원본 1장을 저장한다.

## 합성 규칙

코드: `native/lunacore/src/raw_fusion.cpp`, JNI: `raw_fusion_jni.cpp`,
Kotlin 경계: `processing-native/.../NativeRawFusion.kt`.

1. 각 CFA 채널을 `(sample - black)/(white - black)`로 정규화하고 노출시간×ISO 비율을
   적용한다. 원시 잡음 모델 `variance = S*x + O`도 같은 노출 좌표계로 변환한다.
2. 2×2 Bayer 평균 가이드의 작은 박스 평균 후 선명도와 유효 영역 비율로 기준을 선택한다.
   점수가 비슷하면 10% 이내에서는 앞 프레임을 유지해 잡음에 따른 기준 변경을 억제한다.
3. 두 공간 크기에서 전역 평행이동을 찾는다. ±16 RAW 픽셀을 검색하고, 검색 경계 해는
   거절한다. CFA 위상을 유지하는 짝수 이동만 허용하며 보간하지 않는다. 멀리 떨어진
   다른 해/인접 해가 비슷하거나 정방향·역방향 정합이 일치하지 않으면 그 프레임을 뺀다.
4. 모든 CFA 채널이 함께 투표한다. 포화/black 부근, 5개 동일 CFA 이웃의 4σ 초과 차이,
   일관된 방향으로 쌓인 오차는 제외한다. 반경 2·4 RAW 픽셀의 기울기가 다시 나타나는지
   확인해 움직임이나 디테일 불일치를 거른다.
5. 신뢰도 taper × 잡음 역분산으로 병합한다. 기준 가중치는 전체의 최소 1/3이며
   `N_eff=(Σw)²/Σ(w²)`가 1.25 미만이면 기준으로 돌아간다. 변경량은 기준 대비
   `min(센서 유효 범위의 1%, 2σ)` 안으로 제한한다.
6. 계산 결과를 기준 프레임의 black/white/노출 단위로 되돌린다. 불확실한 위치, 광학 black
   영역과 경계는 기준의 원래 uint16 값을 그대로 복사한다. PRE_CORRECTION_ACTIVE_ARRAY
   안에서만 정합 근거와 병합을 계산한다.

독립 구현의 특징은 **수정할 근거와 변경 예산을 먼저 정하고, 애매하면 보존하는 규칙**이다.
정합·역분산·강건 통계는 공통 영상처리 원리이며 학술적 최초나 특허 신규성을 주장하지 않는다.
다른 카메라의 코드/가중치/색감을 가져오지 않았다.

## DNG 저장과 실패

합성 DNG는 선택된 기준의 색 행렬·black/white·방향·렌즈 음영 메타데이터를 사용한다.
합성하지 않을 때는 해당 기준 프레임의 원래 버퍼와 CaptureResult를 쓴다. 공간마다 가중치가 달라지는
합성에 원본의 단일 NoiseProfile을 붙이면 부정확하므로, 새 비공개 임시 DNG에서 선택적
NoiseProfile 태그만 제거한 뒤 MediaStore에 복사한다. 원본 DNG의 메타데이터는 유지한다.

`GeneratedDngMetadata.kt`는 TIFF endian/포인터/디렉터리/범위/겹침을 먼저 검증한 뒤
디렉터리 항목만 줄인다. 픽셀 데이터와 절대 오프셋은 이동하지 않는다. 불완전 파일은
공개하지 않으며 실패 시 해당 호출의 미완료 후보만 정리한다. 저장 공간 부족 등으로
기준 원본 작성도 실패하면 결과는 0장일 수 있으며 실패를 알린다. MediaStore 공개 요청의
응답이 유실되면 해당 후보의 공개 상태를 읽어 확인한다. 상태조차 확인할 수 없을 때는
중복 사진을 만들 수 있는 추가 fallback을 하지 않는다. 기존 사용자 사진은 건드리지 않는다.

`RawSingleOutput`의 가짜 writer 검사에서는 합성 성공/기준 대체/쓰기 실패/취소/공개 상태
불명확/OOM별로 중복 commit을 하지 않는 계약을 검증한다. 실제 디스크 부족·프로세스 종료·
MediaStore 응답 유실을 주입한 검사는 아직 없다. 진단 기록의 실패는 이미 확인된 저장 성공을
실패로 바꾸지 않는다.

## 다음 셔터와 작업 영수증

1.2초는 **다음 셔터 요청을 받을 수 있을 때까지의 목표**이며 최종 파일 저장 기한이 아니다.
`busy`는 센서 수신까지만 유지한다. `processingCount`는 수신 후 처리·저장 중인 작업 수다.
`ready && !busy && processingCount < 2`일 때 다음 셔터를 받는다. 두 건이 차 있으면 먼저
접수한 작업이 완료되어 자리가 생길 때까지 기다린다. 초점/노출 수렴, 장노출, 발열, 저장
지연에 따라 목표를 넘을 수 있으므로 무한 연사나 모든 장면의 1.2초를 보장하지 않는다.

RAW와 AUTO는 `PhotonProcessingGate` 하나를 공유해 무거운 처리를 동시에 실행하지 않는다.
Activity 범위 ViewModel에서 처리하므로 RAW 화면 뒤로 가기·렌즈 변경 중에도 접수한 처리를
계속한다. 입력 RAW는 메모리에만 있으므로 Activity의 영구 종료나 프로세스 종료 시 미저장
작업은 복구되지 않는다. 화면을 떠났다는 것과 백그라운드 서비스를 설치했다는 것은 다르다.

`files/photon-raw-jobs/<jobId>.json`에 최근 최대 32건의 앱 내부 메타데이터를 기록한다.
`files/photon-raw-last-save.json`은 마지막으로 완료한 작업의 호환용 사본이다.
기록은 queued → processing → saved/failed 순서이며 취소·I/O 실패·프로세스 종료 시
중간 기록이 남거나 누락될 수 있다. 영수증은 복구 가능한 이미지 작업 큐가 아니다.

| 필드 | 의미 |
| --- | --- |
| `jobId`, `shutterStartedWallTimeMs` | 촬영 요청 식별과 사용자 시간 기준 |
| `shutterStartedElapsedMs`, `rawReceivedElapsedMs` | 앱 접수와 RAW 버퍼 수신의 단조 시계 |
| `captureMs` | Camera2 촬영 호출의 AE/AF 준비·센서 수신·버퍼 복사 시간 |
| `shutterReadyMs` | 앱 접수 후 실제 다음 셔터 허용 조건이 처음 충족된 시간 |
| `queueWaitMs` | RAW 수신 후 공통 처리 잠금을 얻고 저장 처리를 시작하기까지 |
| `totalMs` | 접수부터 최종 파일 처리 완료까지; 셔터 재활성 시간과 별도 |
| `outputs`, `outputCount` | 이번 작업의 공개 결과 URI와 개수. 정상 저장은 1 |

`shutterReadyMs`는 포화 시 RAW 수신 시각으로 대신 기록하지 않는다. 대기열에 빈자리가 생겨
버튼을 허용할 수 있을 때 기록하며, 화면을 떠나 관측하지 못한 경우 등에는 null이다.
저장 완료 영수증이 먼저 쓰인 뒤 버튼이 재활성되어도 작업별 파일과 해당 마지막 완료 사본의
시각을 갱신한다. 동기화된 병합에서 최초의 비-null 시각을 보존해 늦은 queued/final 기록으로
다시 null이 되지 않도록 한다.
이는 앱 상태 전환의 측정이며 물리 터치에서 화면 픽셀이 바뀌는 시간까지 계측한 값은 아니다.
크기·노출·ISO·기준·이동·실제 NR/EDGE와 처리 단계 시간도 기록하지만 사진 픽셀을 포함하지 않는다.

## 성능과 경계

12MP 합성 작업 하나의 입력 3장 약 75MB + 출력 약 25MB + 가이드 약 37MB에 카메라 버퍼와
런타임이 추가된다. 두 건을 접수하면 입력만 최대 약 150MB가 유지될 수 있고 무거운 합성은
한 번에 하나만 수행한다. 실제 메모리 피크는 실측이 필요하다. 공개 DNG는 약 25MB 한 장이며
합성 DNG의 비공개 임시 파일과 공개 후보를 함께 쓰는 순간에는 추가 공간이 필요하다.
JNI 계산 도중 즉시 취소는 지원하지 않고 전후에 취소를 확인한다.

### v0.6 역사적 동작

v0.6은 원본 DNG 3장을 먼저 공개하고 합성 성공 시 DNG를 추가해 최대 4장을 저장했다.
당시 실제 정지 장면에서 촬영 753ms, 전체 1,937ms를 측정했으나, 이는 v0.7의 단일 저장·
연속 접수·셔터 재활성 측정값이 아니다. 기존 파일은 그대로 보존한다. 당시 검증 기록은
[PHOTON_RAW_VERIFICATION.md](PHOTON_RAW_VERIFICATION.md)의 v0.6 절에 남겨 두었다.

**현재 범위 밖:** subpixel/회전/국소 warp, 큰 손떨림 보정, HDR 브래킷·톤매핑,
초해상도, RAW 현상/JPEG 출력, 딥러닝, 생성 디테일, 긴 연사, 실시간 프리뷰 합성.
미세 손떨림은 짝수 픽셀 정합에 맞지 않아 병합률이 낮아질 수 있다. 실제 피부·옷감·나뭇잎·
움직이는 피사체의 A/B 화질은 자동 합성 테스트만으로 보증하지 않는다.

## 공식 API 근거

- [DngCreator](https://developer.android.com/reference/android/hardware/camera2/DngCreator):
  앱이 만든 packed Bayer 버퍼를 기준 메타데이터와 함께 DNG로 작성.
- [CaptureResult](https://developer.android.com/reference/android/hardware/camera2/CaptureResult):
  timestamp, dynamic black, noise profile의 CFA 순서와 정규화 정의.
- [CameraCharacteristics](https://developer.android.com/reference/android/hardware/camera2/CameraCharacteristics):
  CFA, RAW 크기, active area와 요청 기능.
- [AOSP DngCreator 구현](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/core/jni/android_hardware_camera2_DngCreator.cpp):
  정적 WhiteLevel, 동적 BlackLevel, 원본 NoiseProfile 작성 확인.

실행 근거와 미검증 항목: [PHOTON_RAW_VERIFICATION.md](PHOTON_RAW_VERIFICATION.md).
