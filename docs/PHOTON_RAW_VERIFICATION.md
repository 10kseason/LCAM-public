# PHOTON RAW 검증 — v0.7 계약과 v0.6 역사적 근거

## v0.7 변경과 현재 검증 범위

2026-10-23. RAW 합성 ON은 메모리의 3프레임을 합성한 **DNG 1장만** 공개한다.
합성 근거가 없거나 합성·합성 파일 작성이 실패하면 기준 원본 DNG **1장**을 시도한다.
OFF는 원본 DNG 1장이다. 기존 v0.6의 3+1장 파일은 삭제하거나 다시 쓰지 않는다.
기준 원본 쓰기까지 실패하는 저장 공간 부족 등의 경우에는 0장과 실패 안내가 가능하다.

촬영 잠금과 처리 대기열을 분리했다. RAW 수신 후 다음 셔터를 허용하되 촬영 중인 작업을
포함해 최대 2건만 접수한다. AUTO/RAW의 무거운 처리는 공통 잠금으로 직렬 실행한다.
이미 초점이 잡힌 정지 프리뷰는 AF 재탐색을 생략하고, 연속 촬영 직전 AE/AWB 자동 복귀를
최대 약 1.5초 기다린다. 대기열 포화·노출·초점·발열에 따라 재촬영 대기는 늘어날 수 있다.

**1.2초는 다음 셔터 접수 가능까지의 목표이며 최종 저장 완료 시간이나 보장 수치가 아니다.**
v0.6의 촬영 753ms를 v0.7의 실측 재활성 시간으로 옮겨 적지 않는다.

| v0.7 검사 | 현재 근거 |
| --- | --- |
| 단일 출력 정책·시각 기록 | 최종 `RawSingleOutputTest` 10개, 실패/오류 0인 JVM XML 확인 |
| 검사 내용 | 합성 1개, OFF/기준 대체 1개, 실패 후 대체, 양쪽 쓰기 실패, 취소, 공개 상태 불명확, OOM, 셔터 시각 최초 기록 |
| 최종 빌드·검사 | `output/photon-v0.7.0/quality-gates.log` BUILD SUCCESSFUL, debug/release lint 오류 0 |
| 새 DNG 메타데이터 검사 | schema2 영수증에서 `outputCount=1`과 정확히 하나의 결과 URI를 요구하도록 구현 |
| 영수증 시각 회귀 | 늦은 final/queued 기록이 실제 재활성 시각을 지우지 않는 추가 2개 검사 통과 |
| 실제 사용자 RAW3 촬영 | 0.7.2: 촬영 586ms, 다음 셔터 587ms, 합성 472ms, 최종 저장까지 1,249ms |
| 실제 단일 갤러리 결과 | 합성 DNG 1장, 공개 원본 0장. schema2 영수증과 MediaStore/TIFF 메타데이터 검사 통과 |
| 프리뷰 축·비율 | 0.7.1 수정 후 사용자 정상 확인. DNG 방향과 합성 배치는 변경하지 않음 |

실제 RAW3 근거는 `output/photon-v0.7.2/raw-last-receipt.json`과
`photon-raw-dng-verification.json`에 있다. 2프레임 채택, 4,018,113픽셀 변경을 기록했다.
한 번의 사용자 촬영 결과이며 연속 촬영·발열 조건 전체의 1.2초 보장을 뜻하지 않는다.
사진 픽셀은 열람하지 않았고 자동 검사에서는 실제 셔터를 누르지 않았다.

위 초기 빌드 이후, 저장 commit 후 진단 기록 예외가 발생해도 이미 저장된 파일을 실패로
잘못 표시하지 않도록 오류 처리를 보완했다. 저장 영수증 작성 뒤 실제 대기열이 풀리는 경우에도
재활성 시각을 원자적으로 갱신하고, 늦은 기록이 최초 시각을 덮지 않는 병합을 추가했다.
최종 빌드/lint 결과는 v0.7 산출물의
최종 검증 로그를 기준으로 판단한다. 가짜 writer 검사는 실제 저장장치 오류 주입을 대신하지 않는다.

### 연속 촬영을 확인하는 방법

사용자가 직접 촬영한 최근 작업의 `files/photon-raw-jobs/<jobId>.json`을 비교한다.
최근 최대 32건을 보관하며 `files/photon-raw-last-save.json`에는 마지막 완료 작업만 남는다.

- `captureMs`: RAW 수신까지의 시간. 최종 저장 완료나 다음 셔터 가능 시간을 뜻하지 않는다.
- `shutterReadyMs`: 접수부터 다음 셔터 허용 조건이 처음 충족될 때까지. 두 건 포화 시
  실제 빈자리 발생을 기다린다. 화면 이탈 등으로 관측하지 못하면 null이며 0ms로 해석하지 않는다.
- `totalMs`: 공통 처리 잠금 대기와 합성·DNG 쓰기를 포함한 전체 시간.
- `outputCount`/`outputs`: 성공한 각 작업은 1개 URI. 성공한 연속 2회라면 서로 다른 작업 ID와
  결과 URI 2개여야 하며, 기존 사용자 사진의 총 갤러리 개수로 판단하지 않는다.
- `shutterStartedElapsedMs`, `rawReceivedElapsedMs`, `completedElapsedMs`로 두 작업의
  촬영/처리 겹침을 확인한다. 프레임 내용·사진 픽셀은 검사하지 않는다.

`RawSavedDngTest`는 `-e verifySavedRaw true`일 때만 해당 영수증의 URI를 읽는다.
과거 schema1의 3+1장 영수증도 읽기 호환을 유지하므로, 과거 사진 검사 통과를 v0.7 단일
출력 계약의 실증으로 세지 않는다. schema2는 단일 결과 계약을 별도로 검사한다.

입력 RAW는 메모리에만 남아 화면 이동·렌즈 변경 중에는 처리가 유지되지만, Activity의
영구 종료나 프로세스 종료 시 미저장 작업을 복구할 수 없다. 최대 메모리 피크, 긴 연사,
강제 종료·디스크 부족·MediaStore 응답 유실은 아직 실기기 주입 검사를 하지 않았다.

## v0.6 역사적 검증 기록

2026-10-23, Galaxy S25 Ultra. 로컬 개발 후보이며 공개 배포하지 않았다.
기존 0.5 APK와 변경 전 소스는 보존했다. 결과 파일은 `output/photon-v0.6.0/`에 있다.

## RAW 계산 검사

- 실기기 4080×3060×3 합성 데이터: 최초 **1,649 ms**, 최종 수정 후 **1,648 ms**, 3프레임 채택,
  12,126,665 픽셀 변경, 유효 표본 평균 2.9213.
- 합성 평탄 영역의 잡음 MSE 비율 **0.34237**. 원본 3개 버퍼 해시 불변, 테두리 보존.
- 호스트 검사: 노이즈, 이동+노출 변화, 움직임/포화, CFA별 black 차이, 모호한 정합,
  잘못된 입력, 재현성, active area 밖 보존, 흐린 첫 프레임 대신 기준 선택.
- TIFF 태그 수정: 양 endian, SubIFD/next/Exif·GPS·Interop 연결, payload/offset 불변,
  잘못된 필드/순환/겹침은 수정 전 거절.

이 수치는 인위적 장면의 계산 정확도 근거다. 실제 사진의 화질 향상률로 해석하지 않는다.
RAW 합성 계산 시간에는 촬영, 원본 3개 및 합성 DNG 쓰기가 포함되지 않는다.

## 사용자 실촬영 확인

첫 사용자 RAW3 촬영: 촬영 726 ms, 원본 DNG 3장 저장 440 ms.
4080×3060, 노출 8,333,700 ns, ISO305, 프레임 간격 약 33.33 ms,
실제 NR/EDGE 결과 모두 OFF(0). 합성 입력 검증에서 거절되어 원본 3장만 남았다.
사진 내용은 보지 않고 촬영 영수증의 메타데이터만 확인했다.

읽기 전용 DNG 검사에서 원본 3개 모두 24,999,564 bytes, 4080×3060, 16bit, 방향6,
IS_PENDING=0을 확인했다. Black64/White1023, 잡음 모델 `S=0.000237491903165, O=0`이다.
초기 구현이 유효한 O=0을 거절한 것이 원인이었다. S>0/O=0을 허용하고 음수 및 S/O모두0
거절은 유지하도록 수정하고 호스트 회귀 검사를 추가했다. `dng-first-metadata.json`에는
선택한 TIFF 메타데이터만 있으며 이미지 픽셀을 읽지 않았다.

두 번째 촬영은 합성 오류 없이 1,377 ms에 완료했지만, 정합 근거가 부족해 원본만 유지했다.
이는 합성 성공으로 집계하지 않는다. 이후 휴대폰을 고정하고 불규칙한 무늬의 정지 피사체를
촬영한 세 번째 검사에서는 **원본 3개 + 합성 DNG 1개** 저장이 성공했다.

근거: `raw-final-capture-metadata.json`, `dng-final-verification.log`,
`dng-final-metadata.json`, `dng-final-summary.json`. 합성 파일을 실제로 현상하거나 사람 눈으로
품질 평가한 것은 아니다. 위 소요 시간도 이 장면의 한 번 측정이며 모든 촬영의 2초 보장은 아니다.

별도 합성 실험에서는 대비가 낮은 질감의 정확한 이동도 정합 고유성 기준에 의해 거절될 수
있음을 재현했다(`alignment-diagnostic/results.log`). 실제 두 번째 사진의 원인을 확정한
것은 아니다. 현재의 보존 규칙을 유지했으며, 후속 개선은 기준을 단순히 낮추는 대신
잡음을 고려한 정합 가이드와 독립 표본 검증을 평가해야 한다.

## 산출물

- `LUNA-PHOTON-0.6.0-debug.apk`: 설치된 개발 후보와 SHA-256 일치 확인.
- `LUNA-PHOTON-0.6.0-release-unsigned.apk`: 빌드 검증용, 서명/공개 배포 안 함.
- `source-changes.zip`, `source-changes.diff`, `artifact-manifest.json`: 변경 소스와 체크섬.
- `apk-permissions.txt`: CAMERA 및 AndroidX 내부 signature 권한만 포함.

기존 버전과 사용자 촬영 파일은 보존한다. 검사 종료 후 테스트 APK만 제거하고 앱을 다시 연다.

## 남은 범위

- 실제 장면의 사람 눈 A/B, 움직임/손떨림/색 질감, 세로·가로 RAW 및 다른 RAW 뷰어 비교.
- 저조도 AE/AWB 수렴 실패·초점 실패를 포함한 다양한 환경의 UX.
- 메모리 피크, 장시간 연사/발열, 저장 공간 부족/강제 종료/전원 손실 주입.
- subpixel/회전/국소 정합, HDR/초해상도, RAW 현상 JPEG는 아직 구현하지 않았다.
- 기본 OFF는 유지한다. 높은 합성 비율을 위해 불확실한 프레임을 억지로 섞지 않는다.
