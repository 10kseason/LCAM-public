# PHOTON AUTO HDR — v0.7.5 구현과 검증 범위

2026-10-23. 사용자 기준: **자연스러운 질감·과보정 억제**, 빠른 다음 촬영,
갤러리에 최종 사진 한 장.

AUTO는 기준 JPEG와 짧은 노출 JPEG를 실제로 따로 촬영해 밝은 부분의 정보를
합친다. 이때 제조사 CameraX HDR 확장을 사용하지 않는다. 현재 연결 기기에서 이전에
조회한 4개 노출 카메라의 HDR 확장이 지원되지 않아 앱의 두 노출 경로를 구현했다.
다른 카메라의 색감이나 구현을 복제하지 않았으며, 표준 정합·색공간 변환 자체의
학술적 신규성을 주장하지 않는다.

이 문서의 **49 ms는 이전 v0.7 커널의 합성 입력 연산 한 번**이다. 실제 셔터 복귀 시간,
최종 저장 시간 또는 실사진 화질 향상을 증명하지 않는다.

## 사용자에게 보이는 동작

- HDR과 질감 보호는 각각 켜고 끌 수 있고 촬영 시작 시 설정이 그 사진에 고정된다.
- HDR OFF는 한 번 촬영한다. HDR ON은 조건이 허용할 때 기준과 짧은 노출을 촬영한다.
- AUTO 한 번의 성공한 저장은 갤러리의 최종 JPEG **한 장**이다.
- 처리할 근거가 없거나 처리에 실패하면 완성된 기준 JPEG 한 장을 저장한다.
- 프리뷰는 CameraX 영상이다. 저장 사진의 HDR 합성을 실시간으로 미리 보여주지 않는다.
- RAW 실험 모드는 별도 경로다. 이 문서의 한 장 저장 계약은 AUTO에 적용된다.

v0.5/v0.6 AUTO의 공개 원본·처리본 쌍 저장 방식은 v0.7에서 위 동작으로 대체됐다.
기존에 저장된 사진은 변경하지 않는다. 새 촬영의 기준·짧은 노출 JPEG는 앱 내부에
잠시 보관하며, 최종 사진의 공개 저장이 완료된 뒤 해당 촬영의 임시 파일만 정리한다.
저장 실패·취소 시 완성된 내부 기준 파일은 저장 재시도에 사용할 수 있다.

## 촬영과 처리의 분리

촬영은 CameraX `CAPTURE_MODE_MINIMIZE_LATENCY`, JPEG 품질 설정 95, 플래시 OFF를
사용한다. **v0.7의 0 EV / -2 EV 노출 보정 경로는 v0.7.1에서 대체됐다.** 기존 경로는
기기의 자동 노출 수렴을 기다리다가 시간 예산을 넘겨 두 번째 JPEG를 촬영하지 못했다.
새 경로는 HDR ON일 때만 Camera2 interop으로 센서 노출을 직접 지정한다.

### 수동 브래킷에 필요한 근거

`PhotonMeteredFrame`은 프리뷰의 `TotalCaptureResult`와 콜백 수신 시각을 보관한다.
센서 타임스탬프와 앱 시계의 기준이 다를 수 있어 신선도는 `elapsedRealtime` 수신 시각으로
판단하며, **500 ms 이내** 결과만 사용한다. 다음 조건도 모두 확인한다.

- 선택 카메라의 `MANUAL_SENSOR` 지원, 유효한 노출 시간·ISO 범위와 현재 측정값.
- AE와 AWB가 수렴 또는 잠금 상태이며, AWB 잠금이 지원됨.
- AF OFF 지원. 가변 초점 렌즈는 현재 초점 거리 값이 유효하고, 초점이 맞았으며 렌즈가 정지함.
- 현재 프레임 시간이 노출 시간 이상이며 기기의 최대 프레임 시간 이하임.
- 짧은 노출을 지원 범위로 제한한 후에도 기준과의 명목상 노출비가 최소 1.5임.

메타데이터가 오래됐거나 조건을 충족하지 못하면 수동 브래킷을 시작하지 않고 일반 JPEG
한 장을 촬영한다. 느린 EV 보정 경로로 다시 돌아가지는 않는다. `hdrCaptureReason`에
`manual_metering_stale`, `manual_focus_unsettled` 등 생략 이유를 남긴다.

### 적용과 복원 순서

1. 기존 `Camera2CameraControl` 옵션 전체를 보관한다.
2. 현재 초점 거리를 AF OFF로 고정하고 AWB AUTO 잠금을 요청해 반영을 기다린다.
   AE OFF 상태의 자동 화이트밸런스는 기기 의존적이므로 AWB 잠금을 먼저 적용한다.
3. AE OFF, 프리뷰에서 측정한 노출 시간·ISO·프레임 시간을 등록하고 기준 JPEG를 촬영한다.
   v0.7.2는 설정 완료 future 대기를 JPEG 처리와 겹친 뒤 반드시 회수한다.
   post-RAW sensitivity boost가 보고되면 지원 범위를 확인해 같은 값으로 고정한다.
4. ISO와 나머지 고정값은 유지하고 노출 시간을 기준의 1/4로 요청한다. 최소 노출 시간
   제한을 적용하며, 옵션 등록 후 짧은 JPEG를 촬영하고 해당 설정 future도 회수한다.
5. 정상 완료·실패·취소 모두 기존 interop 옵션 전체를 복원하고 완료를 기다린다.
   복원 실패 시 카메라를 다시 연결하기 전에는 다음 촬영을 허용하지 않는다.

v0.7.3은 ImageCapture 전용 메타데이터 콜백에서 같은 세션의 기준/짧은 촬영 요청,
프레임 번호, AE OFF, 노출 시간·ISO를 확인한다. 짧은 센서 촬영 완료가 확인되면
JPEG 파일 쓰기가 끝나기 전에 복원을 시작한다. JPEG와 복원이 모두 완료되어야 다음
촬영을 허용하며, 콜백 근거가 없으면 파일 완료 후 복원하는 순서를 유지한다.
v0.7.4는 `SYNC_MAX_LATENCY_PER_FRAME_CONTROL`을 보고하는 기기에 한해 정확한 짧은
요청의 시작 콜백에서 복원을 시작한다. 프레임별 원자적 설정 적용이 보장되므로 이후
프리뷰 요청 복원이 이미 시작한 촬영 설정을 바꾸지 않는다. 시작을 촬영 완료로 간주하지
않으며 JPEG·복원 완료와 실제 EXIF 확인은 유지한다. 다른 기기는 완료 콜백을 사용한다.

이 옵션은 반복 프리뷰와 CameraX의 단일 촬영 요청 모두에 적용된다. Future 완료는
반복 결과에 옵션이 제출됐다는 뜻이며, 요청한 노출의 정확한 적용이나 3A 수렴까지
별도로 증명하지 않는다. 저장한 두 JPEG의 **실제 EXIF 노출비**로 합성 가능 여부를
판정한다. 같은 세션에 직접 Camera2 capture 요청을 섞거나 세션을 닫지 않는다.
[Camera2CameraControl 공식 API](https://developer.android.com/reference/androidx/camera/camera2/interop/Camera2CameraControl)

설정 등록 후 촬영 요청을 순서대로 제출하는 동작은 고정된 CameraX 1.6.2의 순차 executor와
still-request 옵션 병합 순서를 로컬 AAR bytecode로 확인했다. 이 내부 순서는 라이브러리
업데이트 시 재검증해야 한다. 취소·예외가 발생해도 설정 future를 회수한 뒤 복원을 기다린다.
두 번째 JPEG와 해당 설정 future가 모두 성공해야 두 노출 입력을 합성에 전달한다.
상세 검증은 [PHOTON_074_VERIFICATION](PHOTON_074_VERIFICATION.md)를 참조한다.

두 번째 촬영을 시작하기 위한 시간 예산은 **1,100 ms**다. 기준 촬영 뒤와 수동 노출 옵션
반영 뒤 각각 남은 시간이 **350 ms 이상**일 때만 다음 요청을 시작한다. 시간이 모자라면
짧은 노출을 건너뛰고 기준 사진을 처리한다. 이미 제출한 촬영을 강제 취소하는 구조가
아니므로, 1,100 ms는 촬영 완료 상한이 아니다.

CameraX 파일 촬영에는 이 경로에서 사용할 개별 요청 취소가 없다. 제출된 파일 콜백과
옵션 복원을 취소 불가능한 정리 구간에서 기다린다. 완료된 기준 파일은 유지하며,
취소됐다는 이유로 센서가 아직 바쁜 상태에서 셔터를 먼저 활성화하지 않는다.

센서 요청과 옵션 복원이 끝나면 무거운 디코딩·합성·저장을 별도로 진행한다.
AUTO와 RAW는 `PhotonProcessingGate.mutex` 하나를 공유해 CPU·메모리를 많이 쓰는
처리가 겹치지 않게 한다. AUTO의 진행 중 작업은 촬영·대기·처리를 합쳐 최대 **2개**다.
진행 중 작업이 2개이면 처리 자리가 비기 전까지 다음 셔터를 막는다. 따라서 처리가
느리게 밀리면 다음 촬영 시간에도 영향을 준다.

## 두 노출에서 변경할 근거를 찾는 방법

구현: `native/lunacore/src/hdr_fusion.cpp`.
연결: `processing-native/.../NativeHdrFusion.kt`.

입력은 같은 크기와 같은 EXIF 방향을 가진 소프트웨어 ARGB_8888 이미지다.
디코딩 색공간을 sRGB로 지정하고, 짧은 노출 이미지는 읽기 전용으로 사용한다.
크기는 가로·세로 각각 64 이상, 전체 1,600만 픽셀 이하로 제한한다.
노출비는 두 JPEG의 EXIF에서 다음과 같이 구한다.

```text
R = (기준 ExposureTime × 기준 ISO) / (짧은 ExposureTime × 짧은 ISO)
지원 범위: 1.5 ≤ R ≤ 8
```

메타데이터가 없거나 유효하지 않으면 추측해서 합치지 않는다. 비트맵의 전체 프레임을
추가 복사하지 않고, 기준 비트맵의 허용된 픽셀만 갱신한다. 원본 JPEG 파일은 이 연산으로
변하지 않는다.

### 1. 보수적인 전역 위치 정합

sRGB 값을 곧바로 노출비에 곱하면 제조사 JPEG 톤 처리 때문에 잘못 거절할 수 있다.
v0.7.3은 주변 8방향의 밝기 순서를 비교하는 census 비용으로 위치부터 찾는다.
클리핑되지 않았고 명암 변화가 있는 점을 최대 512개 선택한다. 규칙적인 표본 격자가
미세한 반복 무늬의 같은 위치만 보지 않도록 격자 내부 위치를 결정적으로 분산한다.

- 기준점이 64개 미만이면 위치 판단 근거가 부족하다고 본다.
- 가로·세로 512 이상인 영상은 1/4 안내 영상에서 ±32 픽셀 후보를 찾고, 1/2 영상과
  원본에서 각각 후보 주변 ±3 픽셀로 정밀화한다. 작은 영상은 원본 ±16 탐색을 유지한다.
- 두 이미지에서 비교 가능한 방향의 밝기 순서 불일치 비율을 비용으로 사용한다.
- 최저 비용이 너무 높거나 다른 이동과 구별되지 않으면 합성을 거절한다.
- 탐색 경계에서 최적값이 나오면 더 큰 이동일 가능성이 있어 거절한다.
- 반대 방향 정합도 수행한다. 양방향 이동 합이 축별 1 픽셀을 넘으면 거절한다.

v0.7.5는 축소 영상에서 비슷한 비용의 후보를 최대 네 개 유지하고 원본의 공통 기준점으로
비교한다. 다섯 번째 후보까지 모호성 범위 안에 있거나, 남겨 둔 후보 중 하나라도 중간·최종
탐색 경계에서 끝나면 전체 합성을 거절한다. 원본의 최저 비용·차순위와의 차이·역방향
검증 조건은 유지한다. 이는 제한된 후보 안의 검증이며 모든 가능한 변환의 유일성을
증명하지 않는다. 홀수 픽셀 이동이 축소 영상의 반 픽셀 오차로 남을 수 있어,
최종 비용 0.15 이하 조건은 원본 단계에서 적용한다. 안내 영상만 축소하며
최종 합성 픽셀과 출력 해상도는 유지한다. 1/4 휘도 안내 영상 두 장의 추가 메모리는
1,600만 화소 입력에서 최대 2MB다. 거절 결과의 shift는 검증된 이동이 아닌 마지막 후보다.

배율·회전·원근·시차를 보정하지 않는다. 서브픽셀 재표본화도 하지 않는다.
대응 위치를 확신할 수 없는 상황에서 디테일을 생성하는 경로는 없다.

### 2. JPEG 사이의 밝기 응답 검증

위치가 맞는 비클리핑 표본에서 선형화한 짧은 노출 휘도와 기준 휘도의 대응을 얻는다.
훈련 표본 최소 128개와 별도 검증 표본 최소 48개가 필요하다. 휘도 순서로 나눈 8구간의
중앙값으로 응답을 추정하고, 최소 4개의 구별되는 절점·충분한 밝기 범위·양의 제한된
기울기를 요구한다. 검증 표본의 85% 이상이 허용 오차 안에 있고 RMSE가 0.035 이하여야 한다.

관측 영역 밖의 추정은 입력 범위의 3배와 최대 관측 입력의 2배 중 작은 폭까지만 허용한다.
그 경계로 갈수록 합성 비중을 0으로 줄인다. RGB 전체에 같은 휘도 배율을 적용하므로
채널별 독립 곡선으로 색 비율을 바꾸지 않는다. 이 대응은 센서 방사량의 복원이 아닌
JPEG 사이의 보정이며, 국소 톤 처리나 움직임이 큰 경우에는 거절될 수 있다.

### 3. 주변의 비클리핑 영역으로 움직임 검사

32 픽셀 간격의 신뢰도 격자를 만든다. 각 지점 주변 ±32 픽셀 안을 8 픽셀 간격으로
확인하고, 기준의 가장 큰 RGB 채널이 50 이상 235 미만인 불투명 픽셀을 증거로 쓴다.
비교할 점이 6개 이상이고, 그중 90% 이상이 검증된 밝기 응답 보정 후 채널별 허용 오차 안에서
일치해야 그 지점을 신뢰한다. 신뢰도는 합성 전에 모두 계산하고 픽셀 사이에 보간한다.

전체가 날아간 넓은 영역에는 비클리핑 대응 근거가 없을 수 있다. 그 경우 기준을 유지한다.
짧은 노출에 무늬가 보인다는 사실만으로 두 촬영의 피사체가 같다고 단정하지 않는다.
이는 움직이는 피사체의 잔상 억제를 우선한 선택이며, 큰 하늘·창문 전체의 복원을 보장하지
않는다. 이 검사만으로 모든 움직임을 검출할 수 있는 것도 아니다.

### 4. 밝은 영역만 짧은 노출의 정보로 교체

기준의 최대 RGB 채널이 **235 미만인 픽셀은 변경하지 않는다**. 짧은 노출의 최대 채널도
250 미만이어야 한다. 알파가 불투명하지 않거나, 대응 좌표가 밖이거나, 밝기 응답으로 보정한
채널 값이 기준과 모순되면 해당 픽셀은 그대로 둔다.

짧은 노출의 선형 RGB에 검증된 휘도 배율을 곱한 벡터를 `S`라고 하자. 최대 채널값 `h`가 0.82 이상일
때만 부드러운 하이라이트 압축을 적용한다.

```text
t = h - 0.75
압축된 최대 채널 = 0.75 + 0.25 × t / (t + 0.25)
후보 RGB = S × (압축된 최대 채널 / h)
```

한 스칼라로 세 채널을 조정해 후보의 선형 RGB 비율을 유지한다. 기준의 최대 선형
채널이 0.82에서 1로 갈수록 smoothstep으로 후보 비중을 늘리고, 주변 신뢰도와 응답 범위의
신뢰도를 곱한다. 한 번의 혼합으로 선형 채널이 0.12 넘게 변하지 않도록 비중을 제한한다.
이후 sRGB로 되돌린다. 이 경로에는 선명화, 윤곽 생성, 중간톤 자동 밝기 상승이 없다.
최종 혼합에는 기준 RGB도 포함되므로 최종 색비율이 항상 후보와 완전히 같다는 뜻은 아니다.

입력 두 장에서 얻은 넓은 명암 범위를 **일반 8-bit SDR JPEG**로 압축하는 HDR 촬영이다.
Ultra HDR gain map이나 HDR 디스플레이용 출력은 구현하지 않았다. gain map이 포함된
입력은 추가 처리를 거절하고 기준 파일로 돌아간다.

## 한 번의 추가 JPEG 인코딩

HDR 결과와 질감 보호를 모두 쓰는 경우 같은 기준 비트맵에서 순서대로 처리한다.
둘 사이에 JPEG를 만들지 않고, 실제 변경이 있을 때만 마지막에 품질 **97**로 한 번
인코딩한다. 따라서 HDR 결과를 JPEG로 저장한 뒤 다시 열어 질감 보호를 적용하는 추가
손실이 없다. 품질 97이 이미 촬영 JPEG에서 잃은 정보를 복원한다는 뜻은 아니다.

두 처리가 모두 꺼져 있거나 실제 변경이 없으면 기준 JPEG 파일을 그대로 복사한다.
디코딩·합성·EXIF 처리 실패 또는 메모리 부족 시에도 완성된 기준 파일을 선택한다.
현재 구현은 처리 도중 하나가 예외로 실패하면 그 촬영의 추가 처리 전체를 포기한다.

완성 파일은 MediaStore의 비공개 pending 상태에 쓴 뒤 성공적으로 공개한다.
촬영별 고유 파일명을 사용해 공개 직후 정리가 중단된 경우의 재시도 중복을 방지한다.
선별한 방향·노출 등 EXIF는 기준 사진에서 이어받고, GPS를 새로 추가하지 않는다.

## 시간 지표와 현재 검증

목표는 사용자 셔터 입력부터 **실제로 다음 셔터가 가능해지는 시점까지 1,200 ms 이하**다.
**v0.7 실사진 검사에서는 이 목표를 달성하지 못했다.** 두 번의 `shutterReadyMs`는
각각 **2,933 ms와 2,223 ms**였다. 두 경우 모두
`exposure_settle_exceeded_hdr_budget`, `hdrApplied=false`, `outputCount=1`로 기록됐고
짧은 노출 촬영을 생략했다. 해당 사진의 질감 보호는 별도로 실행됐으므로 HDR 성공과
혼동하지 않는다. 전체 저장 시간은 각각 3,362 ms와 2,637 ms였다.
증거는 `output/photon-v0.7.0/auto-latency-failure-first.json`과
`output/photon-v0.7.0/auto-latency-failure.json`이다.

이 실패의 노출 보정 대기를 없애기 위해 v0.7.1 수동 센서 경로를 구현했다.
v0.7.2에서는 실제 노출비 4.02521인 2장을 촬영했지만 밝기 관계 검사에서 거절됐고,
다음 셔터는 1,297ms였다. v0.7.3의 밝기 보정과 복원 중첩은 후속 수정이다.
v0.7.3은 두 노출을 촬영했으나 위치 정합을 거절했고, 다음 셔터는 1,212 / 1,222ms였다.
v0.7.4는 정합 범위 확대와 조건부 복원 시점 변경을 적용한다.
**수정 경로의 실제 HDR 합성 및 다음 셔터 1,200 ms 이하는 아직 검증되지 않았다.**
이 문서의 이전 실패를 새 버전의 성능 결과로 바꾸거나, 코드 변경만으로 목표 달성을
선언하지 않는다.

| 지표 | 측정하는 구간 | 포함하지 않는 것 또는 주의점 |
|---|---|---|
| `hdrMs` / 합성 검사 `nativeMs` | 네이티브 HDR 호출 | 촬영, JPEG 디코딩·인코딩, 공개 저장 |
| `captureMs` | 촬영 콜백과 옵션 복원을 포함한 캡처 경로 | 이후 이미지 처리 |
| `captureStagesMs` | baselineConfig / base / shortConfig / short / restore / total | 실행하지 않은 단계는 0; 파일 콜백 지연도 포함 |
| `sensorReadyMs` | 셔터 입력부터 캡처 경로 종료까지 | 처리 대기열로 셔터가 계속 막힐 수 있음 |
| `shutterReadyMs` | 셔터 입력부터 `canCapture`가 실제로 참이 될 때까지 | 앱이 백그라운드거나 재연결 중인 시간도 영향을 줌 |
| `processSaveMs` | 디코딩·합성·인코딩·공개 저장 | 공유 처리 mutex에서 기다린 시간 |
| `totalMs` | 셔터 입력부터 최종 저장 완료까지 | 다음 셔터 가능 시점과 다를 수 있음 |

`within1200Ms`는 측정된 `shutterReadyMs`로만 계산한다. 캡처 예산 1,100 ms 또는
네이티브 49 ms를 이 지표 대신 사용하지 않는다. 연속 촬영에서는 대기열 2개 제한 때문에
첫 사진보다 뒤 사진의 다음 셔터 시간이 길어질 수 있다.

2026-10-23 연결 휴대폰의 **합성 이미지 검사 1회**:

- 크기: 4080 × 3060, 네이티브 HDR **49 ms**.
- 실제 변경: **786,432 픽셀**, 정합 이동 `(0, 0)`, 결과 `aligned`.
- 합성 입력의 밝은 무늬 순서 복원, 선택한 중간톤 유지, 짧은 입력 유지 검사 통과.
- 이 연산의 500 ms 목표는 해당 실행에서 충족했다. 반복 실행 분포·발열 후 성능은 미검증.
- 카메라를 열거나 실제 사진을 자동 촬영하지 않았다.

검사: `PhotonHdrDeviceTest.kt`. 증거: `output/photon-v0.7.0/photon-hdr-benchmark.json`.
호스트 검사는 짧은 노출의 하이라이트 정보 사용, 알려진 이동 정합, 중간톤 무변경,
움직임 모순 시 유지, 평탄한 장면의 정합 거절, 잘못된 노출·입력 검증을 포함한다.

## 남아 있는 한계와 다음 실사진 확인

JPEG는 이미 제조사 ISP의 노이즈 제거, 샤프닝, 색 변환, 비선형 톤 처리를 거쳤다.
EXIF 노출비와 sRGB 역변환만으로 센서의 실제 선형 신호를 정확히 복원할 수 없다.
기기별 톤 곡선 차이가 크면 올바른 두 노출도 합성을 거절할 수 있다. 통과한 결과도
자연스러움·색 정확도·고스트 억제에 대한 실사진 평가가 필요하다.

별도 확인할 항목은 역광 창문·하늘의 디테일, 인물·움직이는 피사체의 경계,
강한 유색 조명, 저조도, 세로/가로, 연속 촬영이다. 기준 파일과 결과의 JPEG 재압축 영향도
함께 비교해야 한다. 측정할 시간은 네이티브 처리뿐 아니라 `shutterReadyMs`와
`totalMs`이며, HDR OFF/ON 및 HDR+질감 보호 조합을 구분한다.

실사진 화질, 1,200 ms 다음 셔터 목표, 긴 연속 촬영·발열·저장 공간 부족 상황은
과거 합성 49 ms 결과로 대체할 수 없다. 후속 실기기 확인에서는 `captureStagesMs`로
옵션 반영·각 JPEG 콜백·복원을 나눠 측정하고, 브래킷이 실제로 완성됐는지와
`hdrApplied`를 별도로 확인한다.
