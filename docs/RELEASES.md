# 릴리스와 보존 정책

## 공개 소스 개인정보 정리 (새 APK 미배포)

진단의 기기 식별 수집·출력과 공개 검증 기록의 기기 식별값을 제거했습니다. 진단 스키마 2와 이전 캐시 정리의 범위는 [진단 개인정보 안내](DIAGNOSTIC_PRIVACY.md)를 따릅니다. 기존 0.16.1 태그·APK를 교체한 변경은 아닙니다.

## 0.16.1 개발 미리보기

RAW AUTO 기본 시작, AUTO 대체 시작, 공통 촬영 화면과 프리뷰 확대 경계 처리를 포함합니다. 공개 준비 과정에서 사용자 EV 보정, 중단된 저장 작업의 복구, 공개 저장 결과가 불명확한 경우의 원본 보존, AUTO 완료 기록의 수명주기 문제를 수정했습니다.

검사 결과는 [0.16.1 감사 기록](CODE_AUDIT_0161.md), 외부 코드 비교 범위는 [출처 검토](SOURCE_PROVENANCE.md)에 기록합니다. 실제 게시된 파일과 태그는 [GitHub 릴리스 목록](https://github.com/10kseason/LCAM-public/releases)이 기준입니다. 설치 APK는 개발 서명이며 정식 배포 서명본이 아닙니다.

## 기존 버전

v0.10.0 개발 미리보기의 태그와 배포 파일은 기존 비공개 저장소에 보존합니다. 개인정보가 포함된 과거 이력을 새 공개 저장소로 옮기지 않습니다. 0.11~0.16의 로컬 검증 기록은 각 버전 문서에 남깁니다. 당시의 검증을 새로운 버전에서 재실행한 결과로 해석해서는 안 됩니다.

## 새 버전 게시 절차

1. 이전 APK와 소스 상태를 보존하고, 대상 버전의 빌드·자동 검사·기기 검사 결과를 구분합니다.
2. 소스·설정·한국어 문서만 내보냅니다. 개인 경로, 서명 키, 기기 보고서, 실사 사진, 캐시, 출력물, 개인 백업 링크는 제외합니다. `python tools/check_public_privacy.py`를 통과하고 이전 커밋도 확인합니다.
3. 새 태그와 새 버전의 APK·SHA-256을 게시합니다. 과거 태그나 배포 파일을 같은 이름으로 교체하지 않습니다.
4. 원격 커밋, 태그, 파일 크기·해시, 공개 상태를 다시 읽어 확인합니다.

개발 서명 키는 저장소 밖에 보관합니다. 다른 키로 서명하면 기존 설치본에 업데이트할 수 없으므로, 원본 키와 이전 릴리스를 임의로 삭제하거나 교체하지 않습니다. 개인 클라우드 백업은 공개 릴리스와 별도이며 그 주소를 문서에 넣지 않습니다.
