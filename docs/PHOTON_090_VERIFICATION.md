# PHOTON 0.9.0 화면 비율 선택과 카메라 조작 화면

2026-10-23. 코드 15 / `0.9.0-framing-debug`를 연결된 휴대폰에 설치했습니다. 빌드, 기기 배치 검사, 사용자가 직접 촬영한 결과·시간 검사를 통과했습니다.

AUTO에 4:3/16:9/21:9 선택과 설정 저장을 추가했습니다. 미리보기는 중앙 FILL_CENTER 자르기를 사용하고 4:3 카메라 세션은 유지합니다. 백그라운드 내보내기에서 선택한 정수 크기로 자릅니다. HDR·디테일 처리는 전체 원본을 보고 최종 JPEG97 인코딩은 한 번만 합니다. 재시도를 위해 작업마다 비율을 보존하며 기준 영상 대체도 선택 비율을 지킵니다. RAW는 전체 DNG를 유지합니다.

어두운 화면, 항상 보이는 비율 버튼, 렌즈·줌 조작, 크고 고정된 셔터를 사용합니다. 처리 스위치와 줌 슬라이더는 별도 스크롤 설정 시트에 둡니다. 세로·가로 셔터 위치를 달리하되 스크롤 열 안에는 넣지 않습니다. 새 의존성은 없습니다. [유지보수 안내](AI_MAINTENANCE.md)에 소스 담당 범위·알고리즘·자르기 계산·성능 및 개인정보 경계·검증 명령이 있습니다.

4080x3060 입력은 4:3 원본 유지, 16:9에서 4080x2295, 21:9에서 4074x1746입니다. 정확한 정수 비율 때문에 이상적 미리보기보다 긴 변 몇 픽셀을 더 자를 수 있습니다. EXIF 방향은 유지하므로 세로 사진은 9:16·9:21로 보입니다. 자르기는 화각·픽셀 수를 줄이며 늘이거나 확대 보간하지 않습니다.

## 자동 검사

- 디버그·릴리스 빌드, JVM 141회, 네이티브 5/5, lint 통과(오류 0, 기존 경고 13, 제안 1). 첫 빌드의 Kotlin 비공개 setter/함수 JVM 이름 충돌은 함수명을 `selectAspectRatio`로 바꿔 수정했습니다.
- 기기 저장·미리보기 12/12: 비율3, 기존 저장7, 미리보기2. 비율 검사는 비율·방향·처리 24조합, 잘못된 HDR 대체 12조합, 불가능한 자르기 1개를 포함합니다. 중앙 좌표, EXIF 방향 1/3/6/8, 정확한 치수, 단일 인코딩·결과, 원본/OFF 바이트 보존, 내보내기 실패 시 비공개 복구를 확인했습니다.
- UI 1/1: 세로·가로×글꼴 배율 1/1.35×비율 3개, 총 12배치. 뷰파인더 기하와 셔터·비율 버튼 노출 영역이 통과했습니다. 첫 시도는 오래된 접근성 스냅샷을 사용해 실패했고 현재 클릭 노드를 다시 얻어 통과했습니다. 테스트 구동 수정이며 실패를 성공으로 숨긴 것이 아닙니다.
- PixelCopy 전에 실시간 PreviewView를 명시적으로 INVISIBLE로 만든 앱 창 이미지 4개를 검토했습니다. 실제 사진 픽셀을 촬영하거나 읽지 않았습니다. 화면 이미지·기하 보고서는 로컬 `output/photon-v0.9.0/`에 있으며 카메라 영역은 의도적으로 검게 보입니다.

## 당시 한계

RAW는 전체 센서 DNG를 유지하며 새 비율은 AUTO JPEG 내보내기에만 적용합니다. 자르기는 화각·픽셀 수를 줄이고 원본 외 비율은 처리 OFF여도 JPEG 인코딩이 필요합니다. 획득·준비와 처리는 분리됐지만 가득 찬 처리 대기열은 다음 촬영을 늦출 수 있습니다. 지속 연사와 실제 프레임 대응은 사용자 확인이 필요합니다. 자동 기하 검사는 광학 왜곡이나 미리보기의 완전히 같은 픽셀 경계를 보장하지 않습니다.

## 실제 촬영 검증

사용자가 HDR OFF, 텍스처·디테일 ON으로 세로 16:9와 가로 21:9를 촬영했습니다. 둘 다 `gpu_gles31`을 사용해 선택 영역을 자르고 JPEG 한 번 인코딩·결과 1개를 공개 저장했습니다.

| 선택 | 인코딩 크기 | EXIF 방향 | 다음 셔터 | 자르기 | 처리·저장 |
| --- | --- | --- | --- | --- | --- |
|16:9|4080x2295|6 (세로)|876ms|13ms|356ms|
|21:9|4074x1746|1 (가로)|752ms|9ms|279ms|

두 정확한 기록 URI에서 비율·크기·방향·0보다 큰 크기·소유권·MediaStore 저장 완료가 헤더 검사로 통과했습니다. 사진 픽셀을 읽거나 내보내지 않았습니다. 2개 표본은 다음 촬영 1,200ms 목표를 충족하지만 보편적·지속 연사 보장은 아닙니다. 실제 장면과 미리보기의 시각적 일치는 사용자 판단으로 남겼습니다.
