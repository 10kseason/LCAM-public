# 진단 정보 최소화

## 변경 범위

진단 스키마 2에서는 기기 요약과 기기에서 파생한 캐시 키를 제거합니다. 모델 코드, 제조사, 시험 기기의 OS/SDK 정보, 펌웨어 식별값 및 해시를 읽거나 내보내지 않습니다. 카메라 기능, 해상도, 지원 포맷, 오류 종류는 유지합니다. 공개 검증 기록의 기기 표기는 제품명만 남깁니다.

기능 탐색기의 JSON/Markdown, PHOTON 진단 JSON, 해상도 조사 도구가 대상입니다. PHOTON 저장 파일명은 `capabilities-v2.json`입니다. 스키마 1을 읽는 외부 도구는 제거된 기기 요약 필드를 요구하지 않도록 수정해야 합니다.

## 캐시와 이전 파일

진단 결과는 저장소 인스턴스의 메모리에서만 재사용합니다. 새 인스턴스에서는 다시 조회하므로 펌웨어 식별값을 캐시 키로 사용할 필요가 없습니다. 같은 인스턴스에서 재조회가 실패하면 마지막 정상 결과를 계속 사용할 수 있습니다.

앱 시작 시 비공개 `capability-explorer/`의 이전 리포트·키와 각 임시 파일, `photon-reports/`의 이전 스키마 공유 임시 파일만 정리합니다. 삭제 실패는 경고로 남깁니다. 이전 디스크 리포트를 다시 읽거나 새 공유에 재사용하지 않습니다. 사용자 선택 위치에 저장한 리포트, 사진, 새 스키마 공유 파일은 삭제하지 않습니다.

조사 도구가 앱 비공개 영역에 남긴 `photon-resolution-metadata.json`과 `photon-capabilities-live.json`도 이전 스키마이거나 기기 요약이 남아 있거나 JSON이 손상된 경우 정리합니다. 기기 요약이 없는 새 스키마 리포트는 보존합니다.

## 검증 방법

```powershell
python tools/check_public_privacy.py
.\gradlew.bat :domain:test :app:testDebugUnitTest :feature-diagnostics:test spotlessCheck :app:lintDebug :app:lintRelease :app:assembleDebug :app:assembleDebugAndroidTest --no-configuration-cache
```

리포트 회귀 검사는 기기 필드 부재와 카메라 기능·오류·문자열 이스케이프 보존을 확인합니다. 이전 캐시 정리 검사는 최종·임시 파일 제거, 반복 실행, 관련 없는 파일과 디렉터리 보존을 확인합니다. 정적 검사는 알려진 기기 코드 형태와 식별값 접근을 차단하며 모든 개인정보의 부재를 증명하는 검사는 아닙니다.

## 적용 한계

- 현재 소스를 정리해도 이전 Git 커밋·태그에는 정보가 남습니다. 이력 재작성이나 저장소 재생성은 별도 결정이 필요합니다.
- 이미 배포된 APK와 사용자가 이미 저장·공유한 리포트는 이 소스 변경으로 바뀌지 않습니다.
- 사진의 EXIF/DNG 메타데이터와 제조사별 카메라 특성 값 전체는 이번 진단 식별 필드 제거와 별도 범위입니다.
- 자동 검사·빌드 성공은 실제 기기의 설치 업데이트와 촬영 검증을 대신하지 않습니다.
