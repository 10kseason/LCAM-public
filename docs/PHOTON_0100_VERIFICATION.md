# PHOTON 0.10.0 미리보기 조작과 최근 사진

검증된 개발 빌드이며 versionCode16 / `0.10.0-controls`입니다. 이전 APK와 수정 전 소스는 버전별 출력 폴더에 보존했습니다. 배포 이력은 RELEASES.md를 참고하세요.

## 동작과 선택 이유

- 뷰파인더를 누르면 AF 표시와 EV 조작이 나타납니다. 길게 누르면 해제하거나 구도를 바꿀 때까지 AF를 유지합니다. 이는 AF만 고정하며 노출은 선택적 보정을 더한 자동 상태입니다.
- EV는 연결된 카메라의 실제 범위·단위를 사용하고 비동기 요청과 오래된 콜백 방어를 적용합니다. 직렬 촬영 대기를 추가하지 않습니다. 렌즈를 다시 연결하면 EV가 0으로 돌아갑니다. 촬영마다 요청·적용·보고 인덱스를 남기고 제공된 ExposureBiasValue를 처리 JPEG에도 유지합니다.
- 격자·수평계는 기본 OFF이며 미리보기 보조 설정을 저장합니다. 사진에는 영향을 주지 않습니다. 수평계는 ON 및 RESUMED 상태에서만 중력·가속도계를 사용하고 화면 회전을 처리하며 약 100ms 간격으로 표시를 갱신합니다. 안정된 화면 수평을 추론할 수 없으면 숨깁니다.
- 최근 사진은 크기가 제한된 앱 자체 마지막 저장 기록과 백그라운드 128픽셀 썸네일을 사용합니다. 셔터는 중앙에 유지하며 썸네일 해독을 카메라 획득·처리 mutex에 넣지 않습니다. 설정 또는 길게 누르기로 JPEG 보기 앱을 고르고 구성 요소를 저장하며 실패 시 선택기로 대체합니다. 명시적 사용자 조작으로만 외부 앱을 열고 그 URI 하나에만 읽기 권한을 줍니다.
- 기존 텍스처·디테일·HDR·비율·RAW 센서 선택·합성 커널은 변경하지 않았습니다.

## 검증 결과

- 전체 디버그·릴리스·테스트 APK 빌드, 서식, JVM 146회, 네이티브 5/5 통과. lint 오류 0개, 경고 16개, 제안 1개입니다. 경고는 기존 의존성·대상 13개와 새 선택적 KTX 문법 제안 3개를 포함합니다. 초기 서식 실패를 수정했고, 초기 컴파일의 노출 프로퍼티 setter/메서드 JVM 이름 충돌은 `adjustExposureEv`로 해결했습니다. 수정 후 전체 검증이 통과했으며 실패 로그도 보존했습니다.
- 기기 조작·저장 22/22: 뷰어4, 초점·노출2, 미리보기2, AUTO 저장7, 비율3, 텍스처·핀치4. 합성 처리 JPEG는 ExposureBiasValue=1/3을 보존합니다. EV+1.0의 요청, CameraX 완료, 실제 미리보기 메타데이터가 인덱스 10으로 일치했고 재연결 후 0으로 복원됐습니다. 길게 누름→짧게 누름, 줌·비율·재연결·해제는 오래된 AF 상태를 무효화합니다. 시험 장면의 자동 AF 시도는 FAILED를 보고해 고정을 올바르게 해제했습니다. 이는 광학 선명도 검증이 아닙니다.
- UI 1/1은 보조 기능 ON 상태의 세로·가로, 글꼴 1/1.35, 비율 조합 12개를 다룹니다. 셔터·버튼 노출과 미리보기 비율이 통과했습니다. PreviewView를 INVISIBLE로 만들고 LocalInspectionMode=true로 최근 썸네일 해독을 끈 뒤 화면 이미지 4개를 검토했습니다. 실제 사진 픽셀을 촬영·읽지 않았습니다. 뷰어 검사는 합성 Intent를 가로채며 외부 앱을 실제로 열지 않습니다.
- 아래 사용자 촬영 2개의 실제 헤더 검사 1/1 통과. 각각 앱 소유의 완료된 비어 있지 않은 JPEG 1개, EXIF6, 4080x3060을 확인했습니다.

## 실제 촬영 시간

사용자 직접 AUTO 촬영이며 HDR OFF, 텍스처·디테일 ON입니다. 사용자에게 격자·수평계 활성화를 요청했지만 해당 스위치 상태는 촬영 기록에 별도로 남지 않았습니다. 두 기록 모두 터치 초점 성공, 0EV, `gpu_gles31`, 최종 인코딩 1회, 대체 처리 없음입니다.

| 촬영 순서 | 다음 셔터 | 처리·저장 | 최종 저장 완료 | 결과 수 |
| --- | --- | --- | --- | --- |
|1|954ms|350ms|1307ms|1|
|2|860ms|313ms|1175ms|1|

두 다음 셔터 시간은 1,200ms 이내이며 최종 저장 완료는 별도입니다. 누름 간격이 약 5.8초이므로 가득 찬 대기열의 지속 연사 상한을 증명하지 않습니다. 저장 사진 픽셀은 검사하지 않았습니다. 보기 앱 선택은 휴대폰에 저장됐으며 근거에는 그 여부만 남기고 앱 이름·구성 요소는 남기지 않았습니다.

1,200ms 목표는 셔터 누름부터 다음 촬영 허용까지입니다. 대기 작업은 2개로 제한하며 장면·AF·가득 찬 대기열은 준비 시간에 영향을 줄 수 있습니다. 이 버전의 관측 시간은 실제 사용자 촬영만으로 판단합니다.
