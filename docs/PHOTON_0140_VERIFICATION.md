# PHOTON 0.14.0 로컬 후보 — RAW AUTO 하늘·거리 톤

2026-10-24. 사용자의 목표는 하늘·구름 색과 읽을 수 있는 거리·건물 암부를 자연스럽게 함께 담는 사진입니다. 별도 자동 렌더러의 첫 단일 RAW 단계이며, 한 노출로 임의의 장면 명암 범위를 모두 담는다는 주장이 아닙니다. 당시 게시하지 않은 후보입니다.

## 제품 동작

- 새 시작은 일반 AUTO를 유지합니다. **보정 설정 → RAW AUTO 열기 · 하늘·거리 (실험)**에서 진입합니다.
- 별도 Activity 범위 모델로 자동 노출·WB·초점, 터치 AF/AE, 기존 후면 광학 핀치 단계를 제공합니다. 수동 Pro·RAW3 합성은 일반 RAW의 기능입니다.
- 렌즈가 제공한 보정 범위로 반올림·제한한 약 -2/3EV에서 시작합니다. 의도적인 시작 편향이며 장면별 하이라이트 측광은 아닙니다. EV 미지원은 0입니다.
- **기본/자연스럽게/더 밝게**의 암부 강도는 0/0.35/0.6, 기본 선택은 자연스럽게입니다. 기본은 추가 암부 항만 끄며 RAW 현상·노출 복원·하이라이트 곡선은 유지합니다. 프로세스 내 Activity 재생성에서 유지하지만 일반 AUTO나 새 시작 모드를 대체하지 않습니다. 셔터 시점의 강도를 작업에 복사합니다.
- 전체 센서 JPEG97 1개를 출력합니다. 미리보기는 장치 미리보기로 최종 톤·색을 실시간 표시하지 않습니다. 채워진 미리보기보다 저장된 전체 센서에 더 넓은 영역이 포함될 수 있습니다.
- 필수 메타데이터·렌더 실패는 기준 DNG 1개를 공개 저장하고 명확히 알립니다. RAW를 지원하는 뷰어가 필요하며 원본을 몰래 중복 공개 저장하지 않습니다.
- 획득·처리를 분리하고 동시 작업 2개·공통 처리 mutex를 유지합니다. 종료 보호에 RAW AUTO도 포함합니다. 새 서비스·권한은 없습니다.

## 처리 흐름과 선택 이유

검증된 Camera2 획득 경로, 물리 RAW 메타데이터, 잔여 LSC, WB/CCM, 기존 Bayer 보간을 재사용합니다. 8비트 양자화 전에 별도 자연스러운 톤 진입점을 추가하고 일반 AUTO·RAW 합성·Night GPU 커널은 교체하지 않습니다.

단일 프레임은 기존 기준 표현을 얻기 위해서만 `NativeSerNight.prepare/fuse(enabled=false)`를 거칩니다. 다중 프레임 근거나 SER 공간적 밝기 상승은 없으며 자연 렌더러는 Night의 상위 비트 밝기 값을 명시적으로 무시합니다.

우선 **보고된** 음의 노출 보정을 `2^(-EV)`로 복원하되 1..4로 제한합니다. 노출 적용 후 음수가 아닌 RGB 최댓값 `t`에 대해 암부 항은 `strength * 0.18 * t/(t+noiseFloor) * t/(t+0.10)`입니다. 결과가 0.65를 넘으면 C1 연속 하이라이트 곡선 `0.65 + 0.35*(v-0.65)/(v-0.30)`을 적용합니다. 공통 RGB 배율로 인코딩 전 양의 채널 비율을 보존하고 검정은 0으로 유지합니다. 두 곡선은 단조·전역 방식이므로 국소 톤 경계 후광을 만들지 않습니다. 밝은 색 압축은 표현상 절충이며 완벽한 색상 지각이나 하늘 분류기가 아닙니다.

노이즈 하한은 정규화 신호 0.02의 기기 노이즈 프로파일과 보수적인 WB·행렬·음영 게인 상한으로 추정하고 0.001..0.1로 제한합니다. 메타데이터가 없거나 잘못되면 0.01을 쓰고 강도는 0.35 이하입니다. 약한 신호의 과도한 상승을 줄일 뿐 노이즈 제거·교정된 장면 SNR이 아닙니다. 기존 센서 포화 여유 보호를 유지하며 잃어버린 RAW 색·세부를 재구성하지 않습니다.

초기 구현은 CPU 전용입니다. 기존 스칼라 색 구현을 재사용해 정확성·호환성 검토를 단순하게 했습니다. GPU 가속은 실제 처리 비용을 측정한 뒤 판단해야 하며 필요성·우위를 가정하지 않습니다. 모든 장면에서 1.2초 준비를 약속하지 않습니다.

## 저장과 실패 경계

`RawAutoPhotoStore`는 전용 비공개 `photon-raw-auto-pending`과 `Pictures/LUNA PHOTON RAW AUTO` 아래 `PHOTON_RAW_AUTO_<uuid>`를 사용합니다. 렌더 전에 기준 DNG를 쓰고 동기화합니다. JPEG 인코딩·메타데이터·완전성 검사 후에만 준비 표식을 남기므로 메타데이터 단계가 실패한 인코딩 결과를 복구 중 실수로 공개하지 않습니다. 크기 제한된 기존 RAW 작업 기록에는 파이프라인 이름을 남깁니다.

공개 저장은 두 확장자에서 앱 소유의 정확한 작업 ID만 찾습니다. 이미 완료됐으면 그 결과를 반환해 재시도 때 다른 형식을 추가하지 않습니다. 실패한 대기 행은 제거하고 비공개 파일은 완료 후에만 삭제합니다. 공개 저장 실패는 진행 작업이 없을 때 재시도 버튼을 표시합니다. 복구는 재촬영 없이 준비 JPEG 또는 기준 DNG를 내보냅니다. 메모리 획득 중 또는 완전한 기준·기록을 영속 저장하기 전 강제 종료는 복구할 수 없으며 프로세스 사망·전원 상실 전체를 보장하지 않습니다.

## 검증

- 초기 Kotlin setter 이름 충돌과 서식 줄 길이 위반을 수정했습니다.
- 전체 통과: JVM 170회, 네이티브 7개, Spotless, 디버그·릴리스 lint, 디버그·릴리스·androidTest APK. lint는 각 오류 0, 경고 16, 제안 5입니다.
- 네이티브 검사는 전체 회색 코드 순회 36개, 고정 검정, 제한된 암부 상승, 노이즈 하한 효과, 하이라이트 계조, 독립 배정밀도 곡선, 채널 비율, Night 밝기 비트 격리, 잘못된 매개변수 출력 불변을 다룹니다.
- 기존 SER는 CFA 4배치·음영·상위 밝기 값을 포함한 무작위 합성 장 256개에서 0.13 기준과 일치했습니다. 두 해시는 `10854724764954676885`이며 기존 기준 출력 검사도 통과했습니다. 근거: `native-tone/host-test.txt`, `native-tone/legacy-compatibility.txt`.
- 사용자가 0.14 설치·무촬영 검사와 임시 합성 영상 공개 저장·정리를 승인했고 앱·테스트 APK 설치가 성공했습니다.
- 기기 RAW AUTO·시작·권한·종료 6개 통과. 자연 모드 재생성·강도 보존, JNI 기준 일치, 전체 해상도 렌더, 합성 단일 결과 저장·실패 정리를 검사했습니다. 합성 공개 결과는 정확한 URI로 삭제했습니다.
- 기기 회귀 8개 통과: RAW Pro, RAW 광학·공개 카메라 재열기, Night 준비·재열기, 기존 CPU/GPU 색·합성. 선택된 전체 14개에 생략은 없습니다.
- 합성 4080x3060 평탄장의 CPU 렌더 1회는 1,177ms였습니다. 촬영·패킹·DNG 보존·JPEG 인코딩·공개 저장·실제 LSC 비용을 제외하며 다음 셔터·전체 저장·모든 장면의 상한이 아닙니다. 실제 사진을 촬영하지 않았습니다.

## 남은 화질 확인과 다음 단계

실제 셔터를 자동 조작하지 않았습니다. RAW 획득→DNG·색 추출→저장, 장면별 WB·초점·노이즈·지연·자연스러움 판단에는 실제 사진이 필요합니다. 같은 하늘·거리에서 일반 AUTO와 RAW AUTO의 기본/자연스럽게/더 밝게를 비교해 구름 계조·건물 경계·어두운 잎·사람·교통·평탄 암부 노이즈를 확인해야 합니다. 최대 RAW 크기는 장치에 따라 달라지며 더 큰 센서 모드를 해제하지 않습니다.

이 버전에서는 단일 프레임 색·톤의 시각적 수용 후 다중 노출 RAW 정렬·잔상 억제·선택 합성을 진행하도록 보류했습니다. 실시간 최종 톤 미리보기·학습 노이즈 제거·자동 하늘 검출·일반 RAW 편집기·기존 AUTO 교체도 추가하지 않았습니다. 후속 버전의 구현과 구분해야 합니다.
